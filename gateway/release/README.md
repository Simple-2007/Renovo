# Renovo — шлюз Arduino → сайт

Отправляет замеры температуры с контроллера на https://renovo.leikom.ru/.
Python и никакие библиотеки не нужны — всё внутри `renovo-gateway.exe`.
Прошивку контроллера менять не надо.

## Состав

| Файл | Что это |
|---|---|
| `renovo-gateway.exe` | Сама программа |
| `.env` | Настройки. Ключ доступа уже вписан, менять нужно только `SERIAL_PORT` |

Оба файла должны лежать **в одной папке** — программа читает `.env` рядом с собой.

## Запуск

Открыть PowerShell в этой папке (в проводнике: Shift + правая кнопка на пустом
месте → «Открыть окно PowerShell здесь»).

### 1. Проверить связь с сервером

```powershell
.\renovo-gateway.exe --check
```

Ничего не записывает, только проверяет доступ и ключ. Ожидаемый ответ:

```
Связь с сервером есть.
  устройство:      Arduino UNO — цех (тест) (uno-01)
  датчики:         s1, s2, s3, s4, s5
  замеров в базе:  0
  последняя связь: данных ещё не было
```

Если здесь ошибка — дальше идти смысла нет.

### 2. Найти порт платы

```powershell
.\renovo-gateway.exe --list
```

Плата обычно опознаётся как `USB-SERIAL CH340` или `Arduino Uno`. Найденный
порт вписать в `.env`, строка `SERIAL_PORT`. Сейчас там стоит `COM4`.

### 3. Запустить

**Монитор порта в Arduino IDE должен быть закрыт** — порт занимает только одна
программа.

```powershell
.\renovo-gateway.exe
```

Ожидаемый лог:

```
15:31:04  INFO    Порт COM4 открыт на 9600 бод (без перезагрузки платы)
15:31:06  INFO    Отправлена установка часов: 2026-08-13 15:31:06
15:31:07  WARNING Часы контроллера отдают '2000-01-01 00:00:00' — модуль DS3231
                 не найден или сбит. Время замеров будет ставить сервер.
15:31:07  INFO    запись 148 принята, датчиков: 5
```

**Первая запись появится не сразу — до 3 минут**: в прошивке `MEASURE_INTERVAL`
равен 180000 мс. Предупреждение про часы выводится один раз за запуск.

Результат виден на https://renovo.leikom.ru/

Остановка — Ctrl+C. Программа должна работать всё время, пока нужны данные.

## Все команды

| Команда | Что делает |
|---|---|
| `.\renovo-gateway.exe` | Обычная работа: читает порт и отправляет данные на сервер |
| `.\renovo-gateway.exe --check` | Проверяет доступность сервера и ключ. Порт не трогает, в базу ничего не пишет |
| `.\renovo-gateway.exe --list` | Показывает доступные COM-порты с описанием |
| `.\renovo-gateway.exe --dry-run` | Читает порт и показывает всё, что приходит от платы, **ничего не отправляя**. Ключ не нужен |
| `.\renovo-gateway.exe --debug` | Подробный лог, включая служебные ответы платы |
| `.\renovo-gateway.exe --reset-board` | Перезагружать плату при открытии порта (см. ниже) |

Флаги комбинируются и переопределяют `.env`:

```powershell
.\renovo-gateway.exe --dry-run --port COM3
.\renovo-gateway.exe --port COM3 --key <ключ>
```

### Как проверить, что данные с контроллера читаются

```powershell
.\renovo-gateway.exe --dry-run --port COM3
```

Оставить на 10 минут. Ожидаемое: раз в 3 минуты появляется пара строк —
сырая строка от платы и то, как её разобрала программа:

```
ПОЛУЧЕНО: DATA;73;2000-01-01 00:00:00;26.88;26.81;-99.00;-99.00;-99.00
РАЗОБРАНО: {"seq": 73, "t": {"s1": 26.88, "s2": 26.81}, "age": 0}
(проверочный режим — на сервер не отправлено)
```

Значения `-99` — это неподключённые датчики, они отбрасываются. Сейчас реально
подключены два, поэтому в разобранном виде остаются только `s1` и `s2`.

Если за 10 минут не появилось ни одной строки `ПОЛУЧЕНО` — плата не отдаёт
данные, и проблема не в отправке на сервер.

### Про перезагрузку платы

По умолчанию программа открывает порт, **не дёргая линию DTR**. Это важно:
на Arduino UNO сигнал DTR перезагружает плату, а вместе с ней обнуляется
таймер до следующего замера. Прошивка делает замер раз в 3 минуты, поэтому при
частых переподключениях платы к порту она просто не доживает до первого замера,
и данных нет вообще, хотя внешне всё выглядит рабочим.

Флаг `--reset-board` возвращает старое поведение — может пригодиться, если плата
зависла и её нужно перезапустить, не выдёргивая USB.

## Если Windows ругается на файл

`renovo-gateway.exe` собран из скрипта на Python и не подписан сертификатом,
поэтому SmartScreen может показать «Windows защитила ваш компьютер».
Нажать «Подробнее» → «Выполнить в любом случае». Антивирус иногда реагирует
на такие сборки так же — файл при необходимости добавляется в исключения.

## Что делает программа

* Раз в 10 секунд шлёт плате `PING`. Это обязательно: прошивка выводит замеры в
  порт только пока считает, что ПК на связи, а флаг взводится именно этой
  командой. Без пинга записи уходят на SD-карту, а без карты теряются.
* Разбирает строки `DATA;<номер>;<время>;t1..t5` и отправляет их на сервер.
* Проверяет метку времени. Пока DS3231 не установлен, плата отдаёт `2000-01-01`;
  такие метки игнорируются, время ставит сервер. После установки модуля
  программа сама переключится на его время, настраивать ничего не нужно.
* Значения `-99` (датчик не дал показаний) не отправляет — на сайте такая
  карточка станет серой вместо неверного числа.
* При обрыве сети пишет предупреждение в лог. Накопление данных пока не
  реализовано: то, что не ушло, теряется.

## Если что-то не так

| Сообщение | Причина |
|---|---|
| `could not open port 'COM4': Access is denied` | Открыт монитор порта в Arduino IDE или уже запущена вторая копия программы |
| `Порт потерян (ClearCommError failed...)`, затем `FileNotFoundError` | Плата пропала из системы: проблема с USB. Другой кабель (не только для зарядки), другой порт напрямую без хаба, отключить экономию питания USB в Диспетчере устройств |
| `Ключ устройства не принят` | Испорчен `DEVICE_KEY` в `.env` |
| `Сервер недоступен` | Нет интернета или закрыт доступ к renovo.leikom.ru |
| Порт открыт, но записей нет дольше 4 минут | Плата не отвечает. Остановить программу и посмотреть в мониторе порта на 9600 бод, идут ли строки `DATA;...` |
| `Сервер отбросил сбойные датчики: s3` | Датчик s3 неисправен, остальные пишутся нормально |
| `Запись N без единого исправного датчика` | Все пять датчиков отдают -99, проверить питание линии |

Подробный лог: `.\renovo-gateway.exe --debug`
