# Renovo — тестовый контур мониторинга температуры

Arduino UNO снимает температуру с датчиков DS18B20 и отдаёт её в COM-порт.
Шлюз на ПК читает порт и отправляет данные в API сайта. Сайт показывает
показания в реальном времени и хранит историю в PostgreSQL.

```
Arduino UNO ──USB/COM──> gateway.py ──HTTPS──> Django API ──> PostgreSQL
                                                    │
                                                    └──> https://renovo.leikom.ru/
```

## Состав

| Каталог | Что это |
|---|---|
| `ArduinoV2/WeatherStation/` | **Рабочая прошивка**: DS18B20, SD-буфер, RTC, светодиоды статуса |
| `arduino/renovo_temp/` | Запасной простой скетч: только опрос датчиков, вывод JSON |
| `gateway/` | Шлюз на ПК: COM-порт → HTTP API. Понимает обе прошивки |
| `server/` | Сайт и API: Django 5 + DRF + PostgreSQL. Развёрнут в `/opt/renovo` на VPS |

Файлы `.env` в репозиторий не попадают — рядом лежат `*.env.example`.

Серверная часть развёрнута на VPS 193.47.60.199 в `/opt/renovo`.

## Запуск

### 1. Прошивка контроллера

Сейчас в плату залита `ArduinoV2/WeatherStation`. Она шлёт в порт на **9600 бод**
строки вида:

```
DATA;<номер>;<ГГГГ-ММ-ДД ЧЧ:ММ:СС>;t1;t2;t3;t4;t5
```

Замеры делаются раз в 3 минуты (`MEASURE_INTERVAL` в `config.h`). Записи
выводятся в порт, **только пока прошивка считает, что ПК на связи**, а этот флаг
взводится командой `PING` — шлюз шлёт её каждые 10 секунд автоматически.

Ниже — описание запасного скетча `renovo_temp` на случай, если понадобится
простой вариант без SD и RTC.

#### Запасной скетч renovo_temp

Схема: каждый датчик на своём пине — **D2, D3, D4, D5, D6** (по одному DS18B20
на линию). На **каждой** линии свой подтягивающий резистор **4.7 кОм** между её
выводом DATA и +5 В. Питание VDD и GND — общее.

Если распиновка другая, поправьте массив `SENSOR_PINS` в начале скетча — это
единственное место, где перечислены пины. Номер датчика соответствует позиции
в этом массиве: первый пин — `s1`, второй — `s2` и так далее.

В Arduino IDE через Менеджер библиотек установить `OneWire` (Paul Stoffregen) и
`DallasTemperature` (Miles Burton), затем прошить `arduino/renovo_temp/renovo_temp.ino`.

В мониторе порта на скорости 115200 после старта появится список найденных
датчиков и далее строки вида:

```
# renovo temp node, boot=1477321905
#   s1 (pin D2) = 28FF3A1C04150137
#   s2 (pin D3) = 28FF9A2B05160244
...
# sensors found: 5 of 5
{"boot":1477321905,"seq":1,"age":0,"t":{"s1":23.50,"s2":24.12,"s3":22.81,"s4":25.30,"s5":21.94}}
```

Нумерация привязана к пину, а не к адресу датчика, поэтому замена вышедшего из
строя датчика не сдвигает остальные и не требует перепрошивки: новый датчик
подхватится автоматически на ближайшем цикле опроса.

### 2. Шлюз на ПК

```powershell
cd gateway
pip install -r requirements.txt
copy .env.example .env
```

В `.env` вписать `DEVICE_KEY` — он берётся в админке на странице устройства.
Затем:

```powershell
python gateway.py            # порт определяется автоматически
python gateway.py --list     # посмотреть доступные COM-порты
python gateway.py --port COM3
```

Монитор порта в Arduino IDE при этом должен быть закрыт — порт занимается
одной программой.

## API

Приём данных, заголовок `X-Device-Key: <ключ устройства>`:

```
POST https://renovo.leikom.ru/api/v1/readings
{"boot":815623,"seq":1421,"age":0,"t":{"s1":23.5,"s2":24.1}}
```

Принимается и массив пакетов — это задел под дозаливку накопленного буфера.

Ответ:

```json
{"ok":true,"ack":1421,"received":2,"skipped":[],"now":1786603157}
```

* `seq` — сквозной номер пакета на контроллере. Тройка «датчик + boot + seq»
  уникальна в базе, поэтому повторная отправка того же пакета не создаёт дублей.
* `boot` — идентификатор запуска контроллера, случайный при каждом включении.
  Открытие COM-порта перезагружает плату и обнуляет `seq`; без `boot` сервер
  принимал бы замеры после перезапуска за дубликаты уже записанных и молча
  отбрасывал их.
* `ts` — абсолютное время замера с часов контроллера (DS3231). Приоритетнее
  `age`. Отклоняется, если старше 30 суток или в будущем — так сбитый RTC не
  засорит историю.
* `age` — возраст замера в миллисекундах, запасной вариант для контроллеров без
  часов: сервер считает `ts = now - age`.
* `ack` — сервер подтверждает только после записи в базу.
* `skipped` — датчики, чьи значения отброшены как неисправные (вне диапазона
  −100…300 °C). Остальные значения из пакета при этом принимаются.

Чтение:

```
GET /api/v1/latest              последние значения по каждому датчику
GET /api/v1/series?minutes=30   история для графика
```

## Добавление датчиков

Ничего настраивать не нужно: новый датчик появляется в системе сам при первом
замере с новым ключом — заводится запись датчика, назначается цвет, на странице
добавляется карточка и линия на графике. Название и цвет можно потом поправить
в админке.

## Известные дефекты прошивки WeatherStation

Проверены по коду, чинить их нужно перед тем, как включать накопление:

1. **Буфер на SD не очищается.** `sdClearBuffer()` объявлена в `SDStorage.cpp`,
   но не вызывается нигде — после выгрузки файл остаётся и будет отправлен снова.
2. **Флаг связи с ПК не сбрасывается.** `pcConnected` ставится в `true` по `PING`
   и не снимается никогда: `clearPcConnection()` тоже не вызывается, а
   `PC_PING_INTERVAL` объявлен, но не используется. После первого пинга плата
   навсегда считает ПК подключённым и при реальном обрыве не сохраняет на SD.
3. **Задвоенный префикс при выгрузке буфера.** На SD пишется готовая строка
   `DATA;...`, а `sdSendBuffer()` печатает перед ней ещё один `DATA;`.
   Шлюз это переживает, но чинить стоит.
4. **Подстановка старых значений.** При неудачном чтении и при скачке больше
   `MAX_TEMP_CHANGE` (5 °C) в запись идёт предыдущее значение датчика. Оторванный
   датчик выглядит исправным. Лучше не писать значение вовсе.
5. **Износ EEPROM.** Счётчик пишется по одному адресу каждую запись. При
   трёхминутном интервале ресурс ячейки (100 тыс. циклов) исчерпается примерно
   за 7 месяцев.
